# 02. ドメインルール

この文書は、画面や実装方式に依存しない、ぬいとの不変ルールを定義します。

## 1. 用語

| 用語 | 定義 |
|---|---|
| ひとこと日記／投稿 | 写真、300文字以内の本文、ぬいぐるみ、場所、行動日時を1件として保存する記録 |
| きょうの日記 | 1日分の俯瞰地図、投稿一覧、1000文字以内のまとめを表示・編集するページ |
| 行動日時 | 実際にその場所にいた日時。後から投稿する場合も指定できる |
| 投稿日時 | 投稿をアプリに保存した日時。システムが自動記録する |
| 時刻不明投稿 | 行動日だけが分かり、行動時刻を指定しない投稿 |
| 論理日付 | ユーザー設定の「一日の切り替え時刻」に基づく、ぬいと上の日付 |
| 一日の切り替え時刻 | 論理日付が切り替わる時刻。初期値は00:00 |
| 日記案内時刻 | 「きょうの日記」ボタンを目立たせる時刻。初期値は21:00 |
| 足あと線 | 場所と時刻のある投稿地点を、行動時刻順に結ぶ点線 |

## 2. 投稿本文と日記本文

- ひとこと日記の本文は0〜300文字とする。
- 一日のまとめ本文は0〜1000文字とする。
- どちらも改行を許可する。
- 本文が空でも、写真または場所等があれば投稿を保存できる。
- 投稿が0件の日でも、一日のまとめだけを保存できる。

## 3. 写真

- 1投稿の写真は0〜4枚とする。
- 保存画像は元の縦横比を維持する。
- 保存時に正方形へ強制トリミングしない。
- 一覧や地図のサムネイルでは、正方形の枠へ表示上のトリミングをしてよい。
- 詳細表示では本来の縦横比で表示する。
- 容量を抑えるため、保存前にリサイズ・圧縮する。
- 初期版は静止画のみとする。

## 4. 一日の切り替え時刻

### 4.1 基本ルール

- 初期値は `00:00` とする。
- ユーザーは設定画面から任意の時刻へ変更できる。
- 一日の切り替え時刻は、日記案内時刻とは独立している。

### 4.2 論理日付の算出

行動時刻が分かる投稿の論理日付は、端末で扱うローカル日時と、一日の切り替え時刻から算出する。

擬似コード:

```text
if 行動時刻 >= 一日の切り替え時刻:
    論理日付 = 行動日時の暦日
else:
    論理日付 = 行動日時の暦日の前日
```

`00:00` の場合、通常の暦日と同じになる。

### 4.3 例

切り替え時刻が `04:00` のとき:

| 行動日時 | 論理日付 |
|---|---|
| 2026-09-15 03:59 | 2026-09-14 |
| 2026-09-15 04:00 | 2026-09-15 |
| 2026-09-15 21:00 | 2026-09-15 |
| 2026-09-16 02:00 | 2026-09-15 |
| 2026-09-16 04:00 | 2026-09-16 |

### 4.4 時刻不明投稿

- 時刻不明投稿は、時刻から論理日付を算出できない。
- ユーザーが選択した論理日付へ保存する。
- 新規作成時の初期値は、投稿作成時点の「きょう」の論理日付とする。
- 一日の切り替え時刻を変更しても、時刻不明投稿の論理日付は自動変更しない。

### 4.5 切り替え時刻変更時

一日の切り替え時刻を変更した場合:

- 行動時刻がある投稿は、新設定で論理日付を再計算する。
- 時刻不明投稿は、手動指定された論理日付を維持する。
- 日別地図、足あと線、投稿一覧を再構成する。
- 1000文字の一日のまとめ本文は、保存済みの論理日付に紐づいたまま維持する。
- 保存前に、過去の日別表示が変わる可能性を説明する。

## 5. 日記案内時刻

- 初期値は `21:00` とする。
- ユーザーは設定画面から変更できる。
- 案内時刻は締切ではない。
- 案内時刻前でも「きょうの日記」を開き、編集できる。
- 案内時刻以降は、「きょう」画面の導線を目立たせる。
- 初期版ではプッシュ通知を送らない。
- アプリを閉じていた場合、次回表示時に現在時刻を判定する。

### 5.1 強調表示の期間

各論理日の開始から終了までの区間内で、最初に到来する日記案内時刻から、その論理日が終了するまで強調表示する。

例:

- 一日の切り替え: `04:00`
- 日記案内: `21:00`

この場合、当日 `21:00` から翌日 `03:59:59...` まで、その論理日の「きょうの日記」ボタンを強調する。

## 6. 投稿の並び順

「きょうの日記」画面では次の順序とする。

### 6.1 時刻あり投稿

1. 行動日時の昇順
2. 同一行動日時の場合は、投稿日時の昇順
3. さらに同一の場合は、内部ID等による安定した順序

### 6.2 時刻不明投稿

- 時刻あり投稿の後、末尾へまとめて表示する。
- 時刻不明投稿同士は、投稿日時の昇順とする。
- 「時間不明」と明示する。
- 投稿日時を行動時刻として表示しない。

## 7. 地図と足あと線

- 地図には、その論理日付の場所付き投稿を表示する。
- 場所と時刻の両方がある投稿のみ、足あと線の対象とする。
- 足あと線は行動時刻の昇順で地点を結ぶ。
- 時刻不明投稿はピンを表示できるが、線には含めない。
- 場所がない投稿は地図へ表示しない。
- 足あと線は実際に通った道路やGPS軌跡を示さない。
- 投稿の日時・場所・削除が変更された場合、地図と線を再計算する。

## 8. 地図の公開範囲

- 地図はユーザー本人の記録用とする。
- 他ユーザーが地図を閲覧する機能を設けない。
- 地図の公開URLを発行しない。
- 地図画面にSNS直接共有を設けない。
- ユーザー自身がスクリーンショットを外部投稿する行為は、アプリの制御対象外とする。
- 個人的な印刷・PDFでは、将来的に地図を含める選択肢を設けてよい。

## 9. 日記作成後の投稿更新

一日のまとめを保存した後に投稿が追加・編集・削除された場合:

- 地図を更新する。
- 足あと線を再計算する。
- 投稿一覧を再並び替えする。
- 1000文字の日記本文は変更しない。
- 必要に応じて、日記作成後に記録が更新された旨を表示する。

## 10. 保存と公開

- 初期版の主要な保存先はブラウザ内ローカルストレージとする。
- ブラウザデータ削除、端末故障、端末紛失時には復元できない可能性がある。
- ローカル保存のリスクを初回利用時と設定画面で明示する。
- LINEログインは招待制で段階導入する。クラウド保存、複数端末同期は認証・認可の検証後に有効化する。
