# データベース変更

データベースを安全に変更するための標準手順です。

## 変更前

1. `AGENTS.md` と、存在する場合はDB設計docsを確認する。
2. 現在のスキーマ、migration方式、データアクセス層、関連テストを確認する。
3. 既存データ、互換性、停止時間、rollbackへの影響を整理する。
4. 対象環境と接続先を確認する。本番操作は明示的な許可なしに実行しない。

## 設計

- 主キー、外部キー、NULL、UNIQUE、DEFAULT、CHECKなどの制約を明確にする。
- 実際の検索・結合・並び替えに基づいてインデックスを設計する。
- データ量、日時とタイムゾーン、保持期間、削除方針を確認する。
- 個人情報や機微情報を必要以上に保存しない。
- DB固有機能を使う場合は、採用理由と移植性への影響を確認する。

## migration

- 既存の命名、順序、適用方式に従う。
- 適用済みmigrationを安易に書き換えない。
- データ消失、長時間ロック、後方互換性を確認する。
- 復旧方法またはrollback方針を用意する。
- 空DBへの適用だけでなく、必要に応じて既存データからの移行も検証する。

## 実装

- SQLはパラメータ化し、入力値を直接連結しない。
- transaction境界と同時実行時の整合性を確認する。
- N+1、不要な全件取得、過大な結果セットを避ける。
- DBエラーを握りつぶさず、適切なアプリケーション境界へ伝える。

## テスト

- migration適用
- CRUDと検索条件
- 制約違反、重複、NULL、境界値
- transactionと競合
- 既存データとの互換性

## 完了時

- migration、実装、テスト、DB設計docsの整合性を確認する。
- 実行した検証、未検証の移行経路、運用上の注意を報告する。
