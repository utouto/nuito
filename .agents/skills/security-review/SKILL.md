# セキュリティレビュー

変更に実際に成立し得るセキュリティ・プライバシー問題がないか確認するための手順です。

## 準備

1. `AGENTS.md` と関連docsを読む。
2. データフローと信頼境界を把握する。
3. ユーザー入力、外部入力、Secret、個人情報の経路を確認する。

## 重点項目

### 認証・認可

- 未認証で実行できてはいけない処理がないか。
- 他ユーザーのデータを操作できないか。
- サーバー側で権限検証しているか。

### 入力・出力

- 入力値を信頼していないか。
- SQL Injection、XSS等につながらないか。
- エラーメッセージに内部情報を漏らしていないか。

### API

- Rate Limitや不正利用対策が必要ではないか。
- CORSが過剰に開放されていないか。
- 外部URLを扱う場合はSSRF等を考慮する。

### データ・プライバシー

- 個人情報や機微情報を必要以上に保持していないか。
- ログへ機微情報を出していないか。
- 保存期間や公開範囲が仕様と一致しているか。

### Secret

- APIキー、トークン、認証情報をコミットしていないか。
- クライアントへSecretを露出していないか。

### リポジトリ・供給網

- `SECURITY.md` に実在する非公開報告手段と担当が定義されているか。
- default branchの保護、Secret検出、依存関係・脆弱性検査がリスクに応じて設定されているか。
- CIのtoken権限、外部Action、artifact、forkからの実行が信頼境界を越えていないか。

### AI

- AIへ送る入力に機微情報が含まれないか。
- 外部入力によるプロンプトインジェクションを考慮しているか。
- AI出力を信頼して権限操作やSQL等へ直結していないか。

## 指摘

- 深刻度
- 対象箇所
- 成立条件
- 影響
- 既存防御
- 最小限の修正案

を示す。
理論上の可能性だけを大量に列挙しない。
