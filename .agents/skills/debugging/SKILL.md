# デバッグと原因調査

推測で修正を始めず、再現可能な証拠から原因を切り分けるための手順です。

## 調査開始

1. `AGENTS.md` と関連する仕様、コード、設定、テストを確認する。
2. 期待結果と実際の結果を、観測した事実として分けて記録する。
3. 発生環境、入力、操作、頻度、開始時期、直前の変更を確認する。
4. 調査だけが依頼されている場合は、原因説明までに留めて修正を混在させない。

## 再現

- 最小の再現手順、入力、初期状態を作る。
- 発生条件と非発生条件を比較する。
- 毎回発生するか、時刻、順序、並列性、cache、外部状態に依存するか確認する。
- 再現できない場合は、確認した条件と不足している情報を明示する。
- 本番データやSecretをローカルへ安易にコピーしない。

## 切り分け

入口から順に、実際のsystem境界に沿って確認する。

- UI・client state
- network・API契約
- application・domain logic
- DB・cache・queue
- filesystem・runtime・OS・設定
- 外部サービス・認証・権限

各境界で、入力、出力、状態変化、errorを確認する。一度に複数の仮説を検証せず、確認結果で候補を狭める。

## 仮説と証拠

- 仮説ごとに、正しい場合に観測される結果と反証条件を決める。
- 既存のログ、trace、test、履歴、設定を先に利用する。
- 診断用ログを追加する場合は範囲と期間を限定し、機微情報を出さない。
- 相関と因果を混同せず、症状を隠す回避策を根本原因と扱わない。
- 偶然見つけた別問題は記録するが、同じ修正へ無関係に混在させない。

## 原因確定後

1. 原因を、発生条件とコード・設定上の機序を含めて説明する。
2. 可能なら修正前に失敗する最小の再現テストを追加する。
3. 修正が依頼範囲に含まれる場合は `implementation` と必要なdomain Skillを使う。
4. 修正後に再現手順、対象テスト、関連テストを実行する。
5. 一時的な診断コード、不要なlog、debug設定を除去する。

## 完了時

- 症状、期待結果、再現条件、根本原因、証拠を報告する。
- 修正した場合は変更内容と回帰テストを報告する。
- 原因未確定なら、有力な仮説、否定できた仮説、不足情報、次の確認方法を区別する。
- 本番操作や外部状態変更を行っていないか明示する。
