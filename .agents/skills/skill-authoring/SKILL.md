# Skill作成・整理

Skillを増やしすぎず、発見しやすく保守可能にするための手順です。

## 反復作業を見つけたとき

現在のタスクに限らず今後も同じ操作や判断が必要になると分かった場合は、作業完了時に定着方法をユーザーへ提案する。明示的に依頼されていない限り、元のタスクへ無関係な自動化変更を混在させない。

次の順で、最小の定着方法を選ぶ。

1. 既存のコマンド、npm script、Skill、Agentで解決できないか確認する。
2. 開発者が繰り返す短いコマンド列は、採用済みのtask runnerやpackage scriptへの定着を検討する。
3. scriptだけでは読みづらい処理、Secretの安全な読み込み、分岐や検証を伴う処理は、補助スクリプトとtask runnerの組み合わせを検討する。
4. Codexが繰り返す作業手順や判断基準は、責務が近い既存Skillへの追記を優先する。
5. 既存Skillと責務が明確に異なり、複数タスクで再利用できる場合だけ新規Skillを検討する。
6. 手順ではなく専門的な担当責務や独立したレビュー役が必要な場合は、既存Agentの更新を優先し、必要な場合だけ新規Agentを検討する。

提案には最低限、次を含める。

- 繰り返される操作または判断
- 推奨する定着先
- 定着することで減らせるミスや手間
- 想定するコマンド名、Skill名、Agent名、または変更対象

一度しか使わない操作、数秒で終わる単純な単一コマンド、既存手順で十分に安全な操作は、機械的に自動化しない。

## Skill化する条件

次のうち複数を満たすものを候補にする。

- 繰り返し発生する作業である。
- 複数のタスクやAgentから再利用できる。
- 手順や判断基準を標準化できる。
- 実行ミスを減らす価値がある。
- Codexがタスク内容から自動選択しやすい明確な責務がある。

## Skill化しないもの

- 一度しか使わない局所作業
- 本プロジェクト固有の仕様そのもの
- 単なる技術メモ
- Agentの人格や担当責務
- 特定ファイルだけの一時的な指示
- 既存Skillとほぼ同じ内容

## 構造

基本形:

```text
skill-name/
└── SKILL.md
```

必要な場合だけ追加する。

```text
scripts/
references/
assets/
```

## SKILL.md

YAML frontmatterに少なくとも以下を書く。

- `name`
- `description`

`description` は自動選択の入口なので、次を明確にする。

- 何をするときに使うか
- 何をするときには使わないか
- 他Skillとの境界

本文は命令形で、入力、手順、検証、完了条件を具体化する。

## progressive disclosure

SKILL.mdを巨大化させない。
詳細な参考情報は `references/` へ、決定的な処理は必要に応じて `scripts/` へ分ける。
本プロジェクト固有の仕様は `docs/` を参照し、コピーしない。

## 整理

- 重複Skillは統合を検討する。
- 古いSkillは実装・docsと照合する。
- Skill名を変更する場合は参照箇所を確認する。
- 同名Skillを複数作らない。

## 完了条件

- 責務が一文で説明できる。
- descriptionだけで利用場面を判断できる。
- 他Skillと役割が重複していない。
- 実在するパスやコマンドだけを記載している。
- 開発者の反復操作について、既存task runnerまたは補助スクリプトで十分ではないか確認している。
- Agent化する場合、単なる手順ではなく独立した責務があることを確認している。
